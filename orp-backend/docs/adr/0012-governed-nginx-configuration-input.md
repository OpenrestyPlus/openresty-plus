# 0012：以受控配置输入覆盖目标构建支持的 NGINX 配置

平台以结构化资源承载常见配置，并以绑定明确上下文的受控原生指令片段承载长尾配置。首期通用语法树覆盖 root、events、http、stream、mail 及其合法嵌套块；map、geo、日志格式、缓存/限流 zone 等共享块位于各自合法父上下文。通用语法树表示未知指令及嵌套块并提供指令级 Diff；目标节点实际 `nginx -t` 验证其构建是否接受配置，平台不推断未知指令的业务语义或生效方式，未知指令的 reload/restart 由提交人声明并由不同于提交人的审批人确认，已知指令影响分类由平台规则或模块适配元数据提供。候选制品须在审批前通过受限 SSH 暂存到所有目标节点的非活动目录，并用每个节点的真实二进制、模块和启动描述执行 `nginx -t`；systemd unit 由固定模板生成，并在目标节点执行 `systemd-analyze verify`。全部目标的两类验证成功后才进入审查。审批同时绑定制品摘要和发布计划摘要（目标节点、reload/restart 动作、canary 波次与顺序、健康判据）；任一变化均须重新审批。批准后只能激活同一摘要的字节。审查同时提供语义 Diff、最终配置文本 Diff 和逐节点校验证据；语义 Diff 标示指令重排，文本 Diff 展示确定性制品的全部内容变化。片段不得接管平台控制的根配置、模块加载、include 路径、Lua 执行入口或监听骨架。节点能力不一致时默认阻断整个目标批次，只有显式拆分目标并分别审批后才能分批发布。需要 restart 的配置可由平台执行，但必须逐节点 canary；只有期望制品版本/摘要确认、Control API 操作成功和对受影响监听器/路由的合成探测都通过，才判定节点成功，未知结果停止扩散。失败时转人工决定恢复动作；部分成功时逐节点呈现真实活动版本并暂停批次，不自动回滚已成功节点。历史配置回滚会生成相对当前活动版本的新候选并重新审批。该取舍在通用语法覆盖、运行环境兼容性校验和安全治理之间取得平衡。
